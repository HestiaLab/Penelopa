## 1. 目的与范围

本文档描述 Penelopa 的总体架构、分层与模块职责、运行时数据流、关键技术方案与非功能设计，作为详细设计和代码评审的架构依据。实现级契约、算法公式、文件格式与文件映射见[软件详细设计](软件详细设计.md)；需求定义见[软件需求规格说明书](软件需求规格说明书.md)。

## 2. 系统概述与上下文

Penelopa 是纯浏览器应用：Blazor WebAssembly 负责 UI 与领域逻辑，SkiaSharp 优先通过 WebGL 渲染画布，WebGL 不可用时降级为 CPU 光栅；TypeScript 辅助层负责指针、键盘、拖放、存储与帧循环。应用没有生产后端；显式文档保存在 localStorage 或用户文件，编辑中的恢复副本写入 IndexedDB journal。静态站点可部署到 GitHub Pages；云同步仅定义客户端契约，未注册网关。

```
┌──────────────────────── 浏览器 ────────────────────────┐
│  Blazor WebAssembly (Penelopa.Web)                     │
│    ├─ 编辑页 /            仿真页 /simulation             │
│    ├─ Penelopa.Core      模型 / 历史 / 对齐 / 仿真引擎    │
│    ├─ Penelopa.Rendering SkiaSharp 渲染 / 命中 / 视口      │
│    ├─ penelopa.ts       指针 / 键盘 / 拖放 / 帧循环 / 存储 │
│    ├─ localStorage      penelopa.document (+ backup)    │
│    ├─ localStorage      penelopa.activeSession          │
│    ├─ IndexedDB         journal 自动保存 / 崩溃恢复       │
│    └─ 本地文件          .penelopa.json 导入 / 导出       │
└─────────────────────────────────────────────────────────┘
            静态资源                    GitHub Pages
```

外部交互只有三类：浏览器输入事件、浏览器存储（localStorage + IndexedDB journal）、用户文件系统（通过文件选择与下载）。应用不发起业务网络请求；仅从部署站点加载静态资源与内置样例。云客户端契约存在但生产 DI 未注册网关。编辑页最多打开 3 个文档会话，标签切换活动会话；仿真页使用当前活动文档。

## 3. 设计目标与约束

| 目标/约束 | 说明 |
| --- | --- |
| 浏览器内闭环 | 无生产后端、无账号、无遥测；刷新后提示恢复 journal 或由用户显式 Load |
| 可测试的核心 | 领域模型、历史、对齐与仿真引擎不依赖 Blazor/SkiaSharp |
| 所见即所击 | 渲染、命中与指针使用同一视口变换，支持任意 DPI |
| 按需渲染 | 编辑空闲时不持续绘制；仿真播放时才启用渲染循环 |
| 可逆编辑 | 所有文档修改进入事务历史；导入提供一次性整体回滚 |
| 严格文档边界 | 仅接受 v3，加载与导入执行大小、深度、Id、type id、属性与领域校验 |
| 可停靠工作区 | 编辑页与仿真页使用 Atlas 工作区，区域可调整/折叠/移动 |
| 平台锁定 | .NET 10（LTS）、SkiaSharp 4.154.0、Atlas.Blazor 0.4.0、Astrea.Components 0.9.0；升级需整体评估 |

## 4. 总体架构

### 4.1 分层

| 层 | 项目 | 职责 | 依赖 |
| --- | --- | --- | --- |
| 领域层 | `Penelopa.Core` | 图元模型、属性、坐标与变换、对齐、事务历史、交互控制器、文档序列化、仿真引擎 | 无 UI/渲染依赖 |
| 渲染层 | `Penelopa.Rendering` | SkiaSharp 绘制、颜色键命中缓冲、视口变换、选择框与角柄 | `Core`、SkiaSharp |
| 应用层 | `Penelopa.Web` | 路由、页面、面板、工作区定义、文档存储/文件服务、JS 互操作、仿真 UI | `Core`、`Rendering`、Atlas.Blazor、Astrea.Components、Blazor WASM |
| 浏览器辅助 | `src/Penelopa.Web/ts` | 指针捕获、坐标、滚轮、键盘、拖放、DPR 监听、localStorage、下载、rAF 帧循环 | 浏览器 API |
| 测试 | `tests/` | Core/Rendering 单元测试、Web 组件测试、JS 测试、E2E 与性能基准 | 对应被测项目 |

依赖方向严格单向：`Core ← Rendering ← Web`。`Core` 不引用 Blazor 或 SkiaSharp；`Rendering` 不引用 Blazor。该约束保证领域逻辑可在纯 .NET 测试中验证，也保证渲染与命中逻辑不依赖组件生命周期。

### 4.2 部署视图

构建产物为静态 WebAssembly 站点。GitHub Pages 工作流手动触发，发布时改写 `<base href>` 为项目子路径并生成 `404.html` 副本，以支持 `/Penelopa/simulation` 深链接。应用在浏览器内加载 `.wasm`、托管资源、Atlas/Astrea 样式、Astrea 树键盘模块与已编译的 `wwwroot/js/penelopa.js`。

## 6. 运行时数据流

### 6.1 编辑输入与渲染

```
浏览器指针/滚轮/键盘
  → penelopa.ts（坐标、捕获、rAF 节流、语义回调）
  → CanvasPanel（CSS→世界坐标、命中测试）
  → CanvasRenderer.HitTestSelection（角柄 → 颜色键图元 → 并集框）
  → EditorInteractionController（选择/拖拽/缩放/钻取/平移）
  → PrimitiveService（事务、属性与结构修改、选区规范化）
  → DocumentChange（Structure/Selection/Geometry/Transient）
  → CanvasPanel / 图元树 / 属性面板（状态投影）
  → CanvasRenderer.Render（按需 Invalidate）
```

画布渲染与命中共享 `ViewTransform`：可见画布与命中缓冲使用同一矩阵绘制，命中像素映射回图元。颜色键每帧重建，仅需在一次“渲染→命中”周期内稳定。

### 6.2 文档持久化与文件 I/O

```
编辑页/仿真页 Save
  → SimulationConfigStore.ExportActive()（排除 Dormant、按文档顺序）
  → DocumentSerializer.Serialize（v3）
  → DocumentStorage：读取旧值 → 写 backup → 写 penelopa.document
  → Saved 事件（使导入回滚失效）

Import
  → DocumentFileService.ReadAsync（扩展名、大小、严格 UTF-8）
  → DocumentSerializer.Deserialize（v3 + 注册表 + 领域校验 + 仿真段容错）
  → ToolPanel 确认（图元/轨道/警告摘要）
  → DocumentImportRollbackService.TryApplyImport（捕获历史/选区/配置）
  → 替换文档、选区、仿真配置（不写 localStorage）

Autosave
  → DocumentJournalService（Structure/Geometry 或配置变更）
  → 防抖 1.5 s → DocumentSerializer.Serialize（v3，Active 配置）
  → SHA-256 → penelopa.writeJournal（IndexedDB，含 documentId/revision/savedRevision）
  → 启动：读取 localStorage 基线 + journal → 较新则提示 Recover/Discard
  → Recover：DocumentFileService.Apply（清空统一历史，不恢复 undo）
```

### 6.4 多文档会话

```
DocumentTabs（新建/切换/关闭，最多 3 个）
  → DocumentSessionManager.ActivateCore
      ├─ 旧会话：ConfigStore.Config → DocumentSession.Config；Journal.FlushAsync
      ├─ Storage.SetActiveKey(会话键)；Journal.SwitchSessionAsync(会话 journal 键)
      ├─ ConfigStore.SwitchDocument(会话图元, 会话配置)
      ├─ ActivePrimitiveService.Attach(会话图元) → UI 刷新
      └─ 写入 penelopa.activeSession（活动 id/名称/存储键/journal 键）
```

既有面板继续注入 `IPrimitiveService` / `DocumentEditor` / 配置与存储服务；代理把它们定向到活动会话。会话切换发出 `Structure|Geometry|Selection` 刷新事件，但不产生历史条目。每个会话独立预算、revision 与存储键；关闭会话丢弃其历史，非空关闭会话进入文档库，活动描述在刷新后恢复单个活动标签。

### 6.3 仿真播放

```
SimulationPage（Stopwatch 单调时钟）
  → penelopa.startSimulationLoop（rAF，busy 时跳过，标签页隐藏时暂停）
  → OnSimulationFrame
  → SimulationRuntime.Advance（基于时间戳，不累加步长）
  → SimulationEvaluator（二分定位 + 插值）
  → 写入 SimulationOverlay（不修改图元属性）
  → Canvas 读取生效值重绘；20Hz 通过 SimulationReadoutChannel 发布读数
  → Stop/离开：SimulationRuntime.Stop 清空 overlay
```

仿真配置编辑与文档编辑进入同一条统一历史（默认 500 步 / 32 MB），按提交顺序撤销；Loop 是播放设置，不进入历史。仿真页的 Ctrl+Z/Y 与按钮均作用于统一历史。

## 7. 关键方案概览

### 7.1 坐标空间与 DPI

世界坐标 Y 轴向上，渲染目标 Y 轴向下；世界原点映射到画布中心加平移。渲染目标按物理像素分配（CSS 尺寸 × DPR），`ViewTransform` 同时服务绘制、命中与覆盖层。DPR 变化保留缩放与平移，仅更新分辨率。

### 7.2 颜色键命中

渲染时为每个可见叶子图元分配唯一颜色键（从 `0xFF000001` 起），绘制到屏下命中位图；指针命中读取像素颜色并映射回图元。命中绘制关闭抗锯齿，避免边缘混色；键耗尽时显式报错而不是回绕到背景色。

### 7.3 事务与历史

每个文档修改都包裹在事务中：首次修改前记录待提交条目，提交时只保存被触及属性的前后值与结构操作（插入/删除/移动，含被删子树引用）。默认预算 500 步 / 32 MB，撤销/重做恢复条目记录的选区；同一节点同一属性的连续编辑在 800 ms 内合并。嵌套事务共享同一 pending，手势只在首次实际修改时开启事务，取消时逆向应用补丁。

### 7.4 选择、钻取与分组

所有选择入口统一规范化，祖先已选中时排除后代，避免双重变换。画布命中返回“根→叶子”候选链，首次点击选最外层，同位置连续点击逐层钻取。分组只接受根级多选，创建 identity 容器并保持世界位置与 Z 序；取消分组只接受根级 identity 容器。

### 7.5 文档格式 v3

文档为 JSON：版本、DocumentId、Revision、图元树（稳定 type id）、选区 Id、可选仿真段与 Extensions。加载执行 4 MiB、10000 节点、深度 64、Id 唯一、type id 与属性领域校验；只接受版本 3，v1/v2 拒绝。仿真段非法时丢弃配置但保留文档；Dormant 轨道在解析前剪除并给出警告。扩展段未知键原样保留并写回。localStorage 保存前把旧负载写入单槽备份。

### 7.6 自动保存与云契约

每个持久提交（结构/几何或仿真配置）在 1.5 s 防抖后把当前文档写入 IndexedDB journal；选区/临时 overlay 不触发。journal 带 `documentId`、`revision`、`savedRevision`、`savedAt`、JSON 与 SHA-256；启动时只提示同一文档且 revision 高于显式保存基线的 journal。恢复走整体替换并清空统一历史，不恢复 undo；显式 Save 更新基线并清理已保存 revision 的 journal，localStorage Load 同样清理旧 journal。云同步只交付 `ICloudDocumentGateway` 契约（GET/PUT/checkpoint、If-Match 与 409 远端快照）与冲突对话框，生产 DI 未注册网关。

### 7.7 仿真模型

仿真配置与图元属性分离，按 `(PrimitiveId, Float 属性名)` 关联。解析阶段把轨道分为 Active 与 Dormant；求值使用首尾夹取与区间插值，`step` 在本区间保持起始值；三次贝塞尔用二分法反解参数。运行时使用 Ready/Preview/Playing/Paused/Finished 状态机；求值只写入 overlay 生效值层，停止、离开或异常时清空 overlay，文档基础值不变。播放使用单调时钟，标签页隐藏自动暂停。

### 7.8 工作区布局

编辑页根分割为主区（比例 0.78）与底部工具组区（0.22）；主区左侧为 Tools/Primitives，右侧为 Document 画布与 Properties，侧栏使用比例轨道和 160–300px 拖拽约束。仿真页根分割为工作区加底部 208px 时间轴；工作区固定左树 220px、右检视器 320px；四个区域只保留移动能力，不可关闭，每次进入重建默认布局。两个页面均使用 Atlas 顶栏/状态栏外壳。

### 7.9 导入回滚

导入前捕获统一历史状态（文档、选区、仿真配置与 undo/redo 条目）；替换在挂起事件通知的状态下执行，避免捕获过程被自身变更清空。成功后保留一次性状态；持久编辑、配置变更、成功保存、再次导入/Load 或刷新后失效。撤销导入不产生新的历史条目，也没有 redo。

### 7.10 可访问性与响应式

画布提供 `role="application"` 与键盘帮助，仿真画布为 `role="img"`；控件使用原生语义并提供可访问名称。状态、错误和警告使用 live region，高频读数不播报。路由切换管理焦点；导入确认把焦点移到主操作按钮。布局在 700–1440 CSS 像素内保持画布可用，窄视口允许侧栏压缩。

### 7.11 多文档会话

编辑页标签栏最多打开 3 个会话；每个会话由 `PrimitiveService`、仿真配置、revision、localStorage 键与 journal 键组成。`penelopa.sessions` 保存多打开会话集合，刷新后恢复全部标签及显式保存内容；每个会话较新的 journal 由该会话的恢复横幅确认。仅一个会话（含未生成 activeSession 的默认会话）启动时恢复显式保存内容，较新 journal 由恢复横幅确认；`penelopa.library` 保存显式保存文档及所有关闭会话，并以 empty/unsaved 标识空会话和未保存条目。切换会话前写回旧配置并 flush 旧 journal，切换后挂接新会话并读取显式保存基线；pending recovery 按 journal 键保留。关闭会话丢弃历史且至少保留一个；含未保存内容的会话关闭前提示；所有关闭会话（含空会话）进入文档库。仿真页提供活动文档下拉切换。

## 8. 非功能设计

| 属性 | 设计措施 |
| --- | --- |
| 性能 | 按需渲染；指针 move 通过 rAF 节流；仿真播放启用 SKGLView render loop，停止后关闭；读数 20Hz 分发；关键帧二分查找；Fit 估算采样上限 512 |
| 可靠性 | 存储/JS 互操作异常转换为结果对象；事务取消精确恢复；导入失败回滚；仿真异常结束会话并清空 overlay |
| 安全性 | 无后端；导入按不可信输入校验；错误单行摘要；不加载远程脚本；CSP 未配置但无业务网络请求 |
| 隐私 | 文档只存于浏览器与用户文件；无遥测；localStorage 使用文档/备份/按会话文档/活动会话键，IndexedDB 使用按会话 journal 键 |
| 可维护性 | 分层单向依赖；纯模型可单测；渲染器可注入视口；TypeScript 层以语义回调隔离 DOM |
| 可测试性 | 颜色键容量起始值可注入；配置存储/运行时/求值器均无 UI 依赖；性能钩子仅在 `__PENELOPA_PERF__` 下暴露 |
| 可访问性 | 原生控件、ARIA、焦点管理、键盘路径、减少动态效果提示、页面缩放允许 |
| 兼容性 | 基于标准 WebAssembly；WebGL 可选，缺失时 CPU 光栅降级；静态部署与子路径兼容；仅 Chromium 自动化验收 |
