## 1. 目的与范围

本文档规定 Penelopa 的测试层级、环境、准入准出准则、覆盖率与性能门禁、缺陷分级和回归要求。测试对象为基线 `48cdf6d` 的源代码、测试套件与静态构建产物；需求编号见[软件需求规格说明书](软件需求规格说明书.md)，本次执行证据见[软件测试报告](软件测试报告.md)。

## 2. 测试策略

采用分层测试：核心领域逻辑以单元测试为主，渲染与视口以单元测试验证数学正确性，UI 组件用 bUnit 验证状态与可访问性接线，浏览器辅助层用 Node 测试验证 DOM 交互，关键用户流程用 Playwright 端到端验证，性能基准独立运行。

| 层级 | 目标 | 不负责 |
| --- | --- | --- |
| 静态门禁 | 构建一致性、格式、依赖漂移、依赖漏洞 | 运行时行为 |
| 单元测试 | 几何、坐标、事务、选择、序列化、仿真模型/求值/状态机 | Blazor 组件与浏览器 |
| 渲染单元测试 | 视口变换、颜色键、渲染与选择框 | 真实 GPU 像素差异 |
| 组件测试 | 面板状态、属性编辑、文件服务、存储、导入回滚、仿真外壳 | 真实浏览器事件 |
| JS 单元测试 | 指针/键盘/滚轮/拖放/DPR/存储/下载/帧循环 | .NET 与渲染 |
| 端到端测试 | 编辑、文档 I/O、仿真、布局、键盘与焦点 | 跨浏览器矩阵、屏幕阅读器 |
| 性能测试 | 空闲 CPU、播放帧率、长时内存与 DOM 稳定性 | 网络/服务器性能 |

测试设计方法：等价类划分、边界值、状态迁移、往返（序列化/反序列化、导入/导出）、故障注入（坏 JSON、存储失败、JS 异常、校验冲突）与回归复现。

## 5. 准入与准出准则

### 5.1 准入准则

1. 代码可编译，所有依赖以 `--locked-mode` 恢复成功。
2. TypeScript 源与提交的 `wwwroot/js/penelopa.js` 一致（无漂移）。
3. 测试依赖已安装：npm 根目录、`tests/e2e`、Chromium。
4. 新增或修改需求有对应 SRS 条目与可验证行为；缺陷修复有复现步骤。
5. 测试数据可用：内置样例、v2 文档、必要的坏数据夹具。

### 5.2 准出准则

1. `dotnet test`、JS 测试、Playwright 全量用例全部通过；跳过项必须仅为 `PERF=1` 性能用例。
2. 覆盖率门禁全部通过（见第 6 节）。
3. `dotnet format --verify-no-changes` 通过；生成 JS 无漂移。
4. npm 两个根目录与 NuGet 依赖审计无 High/Critical；已知中危测试专用风险有记录。
5. 性能基准在 `PERF=1` 下全部通过（见第 7 节），或偏差有明确说明并记录为遗留项。
6. 无未关闭的 P0/P1 缺陷；P2 缺陷有处理计划。
7. 测试报告记录执行日期、基线提交、环境、实测数据与未验证项。

## 6. 覆盖率门禁

覆盖率由 `scripts/check-coverage.py` 合并所有测试程序集的 Cobertura 报告，按源码行取最大命中数，避免重复行拉低结果。

| 范围 | 门禁 | 说明 |
| --- | --- | --- |
| `Penelopa.Core` | 行覆盖率 ≥90% | 整个程序集 |
| `Penelopa.Rendering` | 行覆盖率 ≥85% | 整个程序集 |
| `Penelopa.Core/Simulation/` | 每个文件 ≥90% | 新仿真代码不得藏在平均值后 |
| `Penelopa.Core/Services/DocumentSerializer.cs` | ≥90% | 文件级门禁 |

覆盖率不替代行为验证；新增分支应优先补充断言而非仅为提升数字。

## 7. 性能门禁

性能基准仅在 `PERF=1` 下运行，默认 E2E 跳过并计为跳过项。阈值以 Playwright 断言为准：

| 用例 | 指标 | 门禁 |
| --- | --- | --- |
| 空文档空闲 | 主线程 CPU（3 秒采样） | <5% |
| 500 矩形空闲 | 主线程 CPU（3 秒采样） | <50% |
| 500 图元 + 100 Active 轨道播放 | JS tick/s、.NET frame/s、paint/s（5 秒） | 均 ≥55 |
| 上述播放 Stop 后 | 空闲主线程 CPU（2 秒） | <5% |
| 选中 200 关键帧轨道播放 | tick/s、paint/s（5 秒） | tick ≥59，paint ≥55 |
| 60 秒循环播放 | DOM documents、nodes、listeners、JS heap | documents 增长 ≤1；nodes ≤+200；listeners ≤+2；heap 增长 <8 MiB |

指标口径：tick 是 JS `requestAnimationFrame` 回调尝试数；.NET frame 是实际执行的 `OnSimulationFrame`；paint 是 SKGLView `OnPaintSurface` 回调。三者必须分别记录，不得用 tick 代替绘制帧率。CDP `JSHeapUsedSize` 只覆盖 JS 堆，不包含 .NET WebAssembly 线性内存。

## 8. 缺陷分级与处理

| 级别 | 定义 | 处理要求 |
| --- | --- | --- |
| P0 阻断 | 数据丢失、崩溃、安全漏洞、核心流程完全不可用 | 停止合并与发布，立即修复并回归 |
| P1 严重 | 需求被违背且无合理替代路径；主要用户流程受损 | 当前迭代修复；必须新增回归测试 |
| P2 一般 | 有替代路径或影响局部；非关键校验/文案/布局问题 | 下一迭代修复或记录为遗留项 |
| P3 轻微 | 样式、文案、清理、可维护性建议 | 可排期处理 |

缺陷关闭条件：修复提交 + 至少一个失败前可复现的自动化用例（或说明无法自动化的原因与手工步骤）+ 门禁重跑通过。回归测试必须覆盖触发条件，而不是只覆盖修复后的路径。

## 9. CI 映射

| CI 作业 | 命令 | 失败影响 |
| --- | --- | --- |
| `build`（Ubuntu/Windows） | `npm ci`、`npm run check:js`、`npm run test:js`、JS 漂移检查、`dotnet restore --locked-mode`、`dotnet build`、`dotnet test` | 阻断合并 |
| `format` | `dotnet format Penelopa.sln --verify-no-changes --no-restore` | 阻断合并 |
| `coverage` | `dotnet test --collect:"XPlat Code Coverage"`、`python3 scripts/check-coverage.py` | 阻断合并 |
| `e2e` | `npm ci`（e2e）、`npx playwright install --with-deps chromium`、`npx playwright test` | 阻断合并 |
| `audit` | `npm audit --audit-level=high`（两个根）、`dotnet list package --vulnerable --include-transitive` 并检查 High/Critical | 阻断合并 |

本地等价命令：

```sh
dotnet restore Penelopa.sln --locked-mode
dotnet build Penelopa.sln --no-restore
dotnet test Penelopa.sln --no-build --no-restore
dotnet format Penelopa.sln --verify-no-changes --no-restore

npm ci
npm run check:js
npm run test:js
git diff --exit-code -- src/Penelopa.Web/wwwroot/js/penelopa.js

dotnet test Penelopa.sln --no-build --no-restore --collect:"XPlat Code Coverage" --results-directory artifacts/coverage
python scripts/check-coverage.py

npm ci --prefix tests/e2e
npx --prefix tests/e2e playwright install chromium
npm run test:e2e

cd tests/e2e
PERF=1 npx playwright test tests/perf.spec.ts tests/simulation-perf.spec.ts
```

## 11. 未覆盖范围与限制

- 自动化浏览器仅 Chromium；Firefox/Safari、真实 GPU 驱动与多显示器 DPI 切换未纳入自动验收。
- E2E 为 headless；屏幕阅读器、真实键盘布局与辅助技术组合仅做手工抽查。
- 性能基准依赖本机负载与 Debug 开发服务器，不代表发布构建或低端设备；不设 CI 性能门禁。
- 内存观测仅覆盖 JS 堆；.NET WebAssembly 线性内存未单独测量。
- 未做负载测试、渗透测试、无障碍合规认证与视觉回归截图比对。
- 未覆盖移动端/触摸优先交互、离线缓存与 CDN 故障场景。
